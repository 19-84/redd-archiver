6 CSS Strategy — Coordination with F4 (Visual Themes)

New components need styling. F4 Phase 1 extracts design tokens from the CSS. The order matters.

Option A Metadata CSS first, then F4 token extraction

→
F4 Phase 1
Write CSS normally now, F4 extracts everything (including new components) into tokens in one pass
New CSS uses hardcoded colors, gets refactored later
Option B F4 tokens first, metadata CSS uses vars Rec.
F4 Phase 1
→
F6/F7 CSS
New components use var(--token) from the start, no double-work
F4P1 must land first (it's currently "parallel track")
Option C Write new CSS with vars anyway (partial tokens)
F6/F7 CSS (use existing ~52 vars + define new ones)
New components reference existing var(--...) where available (~52 already exist), define new vars for gaps. F4P1 later unifies everything.
No ordering dependency, partially future-proof
Inconsistent — some vars, some hardcoded; F4 still needs to clean up
